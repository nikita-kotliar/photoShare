# Журнал рішень

Рішення по неоднозначностях ТЗ і технічних виборах.


| ID | Рішення | Чому |
|---|---|---|
| D-01 | Сайт і API на одному домені, nginx сам пересилає `/api` на backend | cookie працюють без зайвих налаштувань CORS |
| D-02 | Після реєстрації користувач одразу заходить в акаунт | менше запитів, і одразу можна показати головну |
| D-03 | Роль користувача беремо з бази на кожному запиті, а не з токена | якщо когось забанили або змінили роль, це діє відразу |
| D-04 | У кожного токена є свій унікальний номер (`jti`) | він потрібен, щоб після виходу токен можна було заблокувати |
| D-05 | Заблоковані токени зберігаємо в PostgreSQL і час від часу чистимо старі | не треба ставити окремий Redis заради простої задачі |
| D-06 | Усі помилки API мають однаковий вигляд: `{ error: { code, message, fields } }` | на фронті один обробник, а помилки можна показати прямо під полями форми |
| D-07 | Без входу відкриті: Welcome, Auth, Profile і PhotoPage. Тільки для своїх: Home, Upload, Settings, Search. Admin бачать лише модератор і адмін | ТЗ позначає приватні сторінки, а світлину можна відкрити за посиланням |
| D-08 | Для світлин є п'ять трансформацій: чорно-біле, сепія, розмиття, поворот і квадратна обрізка | для демо вистачає, і все це вміє Cloudinary |
| D-09 | Теги завжди записуємо малими літерами | щоб `Cat` і `cat` були одним тегом |
| D-10 | У першій міграції лише таблиця користувачів. Решту таблиць додасть Ксенія в TASK-009 окремою міграцією | backend можна запустити і перевірити рано, не чекаючи повної бази |
| D-11 | Poppins для латиниці, а для кирилиці Montserrat | у Poppins немає українських літер |
| D-12 | Для фронтенду є тестовий сервер з готовими даними в `frontend/mock/` | фронтенд можна робити, не чекаючи backend, базу і Cloudinary |
