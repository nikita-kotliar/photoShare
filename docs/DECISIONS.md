# Журнал рішень

Рішення по неоднозначностях ТЗ і технічних виборах.


| ID | Рішення | Чому |
|---|---|---|
| D-01 | Сайт і API на одному домені, nginx сам пересилає `/api` на backend | cookie працюють без зайвих налаштувань CORS |
| D-02 | Після реєстрації користувач одразу заходить в акаунт | менше запитів, і одразу можна показати головну |
| D-03 | Роль користувача беремо з бази на кожному запиті, а не з токена | якщо когось забанили або змінили роль, це діє відразу |
| D-04 | У кожного токена є свій унікальний номер (`jti`) | він потрібен, щоб після виходу токен можна було заблокувати |
| D-05 | Заблоковані токени зберігаємо в PostgreSQL і час від часу чистимо старі | не треба ставити окремий Redis заради простої задачі |
| D-06 | Усі помилки API мають однаковий вигляд: `{ error: { code, message, fields } }` | на фронті один обробник, а помилки можна показати прямо під полями форми |
| D-07 | Без входу відкриті: Welcome, Auth, Profile і PhotoPage. Тільки для своїх: Home, Upload, Settings, Search. Admin бачать лише модератор і адмін | ТЗ позначає приватні сторінки, а світлину можна відкрити за посиланням |
| D-08 | Для світлин є п'ять трансформацій: чорно-біле, сепія, розмиття, поворот і квадратна обрізка | для демо вистачає, і все це вміє Cloudinary |
| D-09 | Теги завжди записуємо малими літерами | щоб `Cat` і `cat` були одним тегом |
| D-10 | У першій міграції лише таблиця користувачів. Решту таблиць додасть Ксенія в TASK-009 окремою міграцією | backend можна запустити і перевірити рано, не чекаючи повної бази |
| D-11 | Poppins для латиниці, а для кирилиці Montserrat | у Poppins немає українських літер |
| D-12 | Для фронтенду є тестовий сервер з готовими даними в `frontend/mock/` | фронтенд можна робити, не чекаючи backend, базу і Cloudinary |
| D-13 | Світлина одразу вантажиться в Cloudinary у TASK-019, трансформації і QR лишаються в TASK-030 | файли не зберігаємо на сервері, тому тимчасове локальне сховище довелося б потім переробляти |
| D-14 | Унікальне посилання на світлину - випадковий `slug` з 12 символів, а не `id` | за посиланням не можна перебрати чужі світлини підряд |
| D-15 | Якщо запис у БД не створився, файл у Cloudinary видаляємо. Якщо при видаленні світлини Cloudinary не відповів, світлина однаково видаляється з БД, а помилка пишеться в лог | у хмарі не лишається сміття, а користувач не бачить помилку через збій зовнішнього сервісу |
| D-16 | Редагувати коментар може лише його автор, навіть ADMIN чужий не змінює. Модератор і адмін можуть тільки видалити | ТЗ дає адміну повний CRUD лише над світлинами. Чужі слова від імені автора виглядали б як підробка |
| D-17 | У картці світлини є рядок «Коментарі» з кількістю, хоч у макеті його немає | ТЗ вимагає показувати кількість коментарів у стрічці |
| D-18 | Сірий текст у картці і тегах - `#627193` (`--color-text-muted`) замість `#697A9E` з макета | `#697A9E` на світлому фоні дає контраст 4.23:1, а для WCAG AA треба 4.5:1. Відтінок майже не відрізняється |
| D-19 | Hover працює лише на пристроях з мишею (`hover: hover and pointer: fine`), на телефоні є тільки pressed | на тач-екранах hover «залипає» після тапу |
| D-20 | Кнопку «Видалити» на чужій картці бачить лише ADMIN, MODERATOR - ні | за ТЗ повний CRUD над світлинами має лише адмін |
| D-21 | Іконку «пароль показано» домальовано в стилі іконки «пароль приховано» | у макеті є лише одна з двох іконок |
| D-22 | Трансформації не змінюють оригінал у Cloudinary: зберігаємо оригінал, а трансформоване зображення - це URL з параметрами. Порядок завжди однаковий: обрізка, поворот, ефект | ефекти не накладаються один на одного в QR-посиланнях (TASK-031), однаковий набір дає однаковий URL і береться з кешу CDN |
| D-23 | Фільтр за датою реєстрації в адмінці рахує дні за UTC і включає обидві межі: `registeredTo=2026-10-01` означає до кінця цього дня | так само рахує мок фронтенду, і адмін очікує, що «по 1 жовтня» включає 1 жовтня |
| D-24 | У стрічці 12 світлин на сторінку, а не 21 як на десктопному макеті | 12 ділиться на 1, 2 і 3 колонки, тож останній ряд завжди повний на всіх екранах |
| D-25 | Пошук, фільтр і сортування над стрічкою додаються в TASK-045, а не в TASK-029 | це функціонал пошуку, який залежить від TASK-043 |
| D-26 | Сторінка «Про нас» є в макеті, але задачі на неї немає, тому `/about` поки заглушка | пункт меню не веде на 404, а сторінку команда може додати окремо |
| D-27 | На мобілці кнопки «Додати світлину» в меню немає, вона є лише у футері, як у макеті | на вузькому екрані макет ставить на її місце поле пошуку |
| D-28 | У десктопному хедері стрілка біля імені відкриває меню «Редагувати профіль» і «Вийти» | у макеті є стрілка, але немає відкритого стану, а вихід за ТЗ має бути доступний |
| D-29 | Плейсхолдер пошуку в меню `#F2F6FF` замість `#CACED7` | `#CACED7` на синьому градієнті не дотягує до контрасту 4.5:1 |
